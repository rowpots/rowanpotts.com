# CLAUDE.md — rowanpotts.com

Static HTML/CSS photography portfolio for **Rowan Potts** (editorial photographer for
*The Breeze* at JMU; Harrisonburg + Northern Virginia). No build step, no framework —
plain HTML + CSS + a couple of vanilla JS behaviors. The goal is a professional,
booking-driving photography site. **Primary job: get paid clients** (the CS background is
a small bio note, not the centerpiece).

## Deploy
- **GitHub Pages from `main`.** Every push to `main` goes live — there is no staging branch.
  Commit directly to `main` (this is a solo repo; do not open PRs unless asked).
- Remote: `https://github.com/rowpots/rowanpotts.com.git` (repo was renamed from
  `rowpots.github.io`).
- Pages serves assets with a **4-hour cache header** — after a deploy, a hard refresh
  (Ctrl+Shift+R) may be needed to see CSS/image changes. The deploy itself is fast.

## Owner workflow (important)
- **Visual/design work is reviewed in-browser before committing.** Default to leaving
  new page/design changes uncommitted and telling the owner what to review, unless they
  explicitly say to commit/push. The owner iterates on taste round-by-round.
- The owner will say "commit and push" when ready — then land it on `main`.

## Architecture

### CSS layering
Every page loads **`/base.css` first, then its own page stylesheet.** `base.css` owns the
shared design system: tokens, the header (`.top`, wordmark + nav + social icons), `.btn`,
`.page_head`, and the `.book` call-to-action strip. There is no site footer. Page CSS owns everything else.

| Stylesheet | Used by |
|---|---|
| `base.css` | **every page** (loaded first) |
| `landing.css` | homepage (`index.html` + `home/index.html`) |
| `gallery_list.css` | galleries index plus the `football`, `concerts`, `volleyball` hubs |
| `gallery_page.css` | all 12 individual gallery pages + mirrors |
| `contact_style.css` | contact page |
| `services.css` | services page |
| `about.css` | about page |

### Dual-file mirror rule
Each page exists twice: a root `<slug>.html` **and** a `<slug>/index.html` mirror (so both
`/contact.html` and `/contact/` work). The mirror is a **byte-identical copy** generated by
`tools/sync-mirrors.mjs`. Special cases: `index.html`→`home/index.html`,
`gallery_list.html`→`galleries/index.html`.

- **Only ever edit the root `<slug>.html` file**, then run `node tools/sync-mirrors.mjs`
  to regenerate mirrors, then `node tools/sync-mirrors.mjs --check` to confirm no drift.
- Never hand-edit a `<slug>/index.html` mirror — it will be overwritten.
- Run sync + `--check` before every commit.

### Design system — clean white (replaced Dark Cinematic, 2026-11-04)
Tokens live in `base.css :root`:
- Colors: white page, `--black:#000`, `--gray:#666`, `--line:#dcdcdc`, `--tint:#f2f2f2` (image
  placeholder). No accent color; the photos carry the color.
- Type: **Instrument Sans** only (`--font`). Headings 700 with tight tracking.
- Layout: `--side` (page gutter), `--gap` (photo gap), `--col:1080px` (galleries column).
- Brand = plain "Rowan Potts" wordmark (`.mark`). Nav: Work / Services / About / Contact plus
  Instagram and LinkedIn icons. "Work" is the `/galleries` URL. No hamburger: nav wraps on phones.

**Style rules from the owner — apply to all design work:** sleek and professional, not soft,
and it must not look AI-made. Reference: Levon Biss's site.
- Do: neutral white and black, one strong sans, square corners, strict alignment, plain direct copy.
- Don't: serif or italic display type, cream or warm tones, gold or decorative accents, gradients,
  shadows, frosted panels, cards, pills, tiny tracked uppercase labels, 01/02/03 numbering, arrows on
  links, middle-dot strings, hover zooms, scroll fades, slogans, three-item feature lists.

**Going back:** the previous Dark Cinematic site is preserved at git tag `dark-cinematic-final`.
See "Restoring the old design" near the end of this file.

## Image pipeline (`tools/`, local-only Node + sharp; not deployed)
Full detail in the owner's memory; the workflow when adding/changing photos:
1. `node tools/optimize-images.mjs [filter]` — reads `<img src>` in root `*.html`, emits
   responsive WebP `[480/960/1600/2400]` + a JPG fallback into
   `/img/<slug-dir>/<slug>-<w>.webp`, auto-orients from EXIF, writes `image-manifest.json`.
   Idempotent (skips srcs already under `/img/`).
2. `node tools/rewrite-html.mjs` — swaps `<img>`→`<picture>` from the manifest (srcset/sizes,
   CLS-safe width/height, `data-full` for the lightbox, hero preload + fetchpriority).
3. `node tools/sync-mirrors.mjs` — mirror the root pages (see rule above).
4. `node tools/move-masters.mjs` — move full-res originals to git-ignored `masters/`.

Other one-off scripts (kept for provenance): `apply-gallery-cover.mjs` (rolled the cover
hero onto gallery pages), `hero-hires.mjs` (3840px hero WebP), `reencode-hero1.mjs`
(re-encoded the first homepage hero frame at q88), `inject-meta.mjs`, `improve-alt.mjs`.

- Masters are backed up in git-ignored `masters/`; the owner's originals also live in
  in-tree source folders (`bestcomp/`, etc.) intentionally.

## Adding a new gallery (established process)
All the tools auto-discover root HTML — no tool edits needed. (First done for
`comedy-show.html`, 2026-07-04.)
1. Drop original JPGs into a source folder in the repo root (e.g. `comedyshow/`).
2. Copy **`baseball.html`** (canonical template) to a new root `<slug>.html`. Update: title / meta
   description / canonical / OG+Twitter block, the `.page_head` h1 and its unique `<slug>_title` id,
   and the images as **plain** tags: one `<img class="image" src="/<folder>/<file>.jpg"
   alt="<Title> photo N">` per photo. The first one is the page's lead photo. Don't hand-write
   srcsets; the pipeline does that.
3. `node tools/optimize-images.mjs <folder>` then `node tools/rewrite-html.mjs`.
4. `node tools/apply-clean-chrome.mjs --finish` marks the first gallery photo eager +
   `fetchpriority="high"` (it is the LCP). Then point `og:image`/`twitter:image` at the optimized
   `/img/<slug>/…-1600.jpg` URL.
5. Add an `<a class="r_item" href="/<slug>">` row to `gallery_list.html` (copy an existing
   row; keep the catch-all "Assorted" row last).
6. `node tools/sync-mirrors.mjs` + `--check`, review in browser, owner commits.

## Adding photos to an EXISTING gallery
No dimension/file-size prep needed on your end — just drop in full-resolution originals;
`sharp` never upscales and caps output at 1600px JPG / 480–2400px WebP.
1. Drop the new JPGs into that gallery's source folder in the repo root (e.g.
   `graduation/`). Source folders are mostly empty day-to-day now — raw originals get
   moved out to git-ignored `masters/` (step 4 below), so don't expect to see the
   existing photos sitting there.
2. Add one **plain** `<img class="image" src="/<folder>/<file>.jpg" alt="<Title> photo N">`
   tag per new photo into that page's `.gallery_masonry` (the root `<slug>.html`, never
   the `/<slug>/index.html` mirror). Don't hand-write srcsets.
3. `node tools/optimize-images.mjs <folder>` (filtered to just that folder — fast, skips
   re-processing the whole site) then `node tools/rewrite-html.mjs` (converts the plain
   `<img>` tags to `<picture>`/srcset from the manifest; safe to run site-wide, it only
   touches un-converted tags).
4. `node tools/sync-mirrors.mjs` + `--check`, review in browser.
5. Optional cleanup, now standard practice: `node tools/move-masters.mjs` (`--dry-run`
   first to preview) moves the newly-optimized originals into git-ignored `masters/`,
   keeping the tracked tree slim. Reversible — move them back out of `masters/` to undo.
6. Owner commits + pushes when happy.

## Conventions & gotchas
- **`picture{display:contents}`** (top of `gallery_page.css`) makes `<picture>` layout-
  transparent so the `<img>` is the layout child. This **breaks CSS `display:grid` cell
  placement** (every image piles into one column). It's fine for CSS-**columns** masonry.
  If you ever need a grid layout, scope `picture{display:block}` to that grid container.
  Same reason: `:nth-child`/`:last-child` on `.image` won't match (the `<img>` is child #2
  of `<picture>`) — target `.gallery_masonry picture:nth-child(...)` instead.
- **CSS links carry a version: `/base.css?v=20261104`.** After changing any stylesheet, bump the date on every root page, then sync mirrors. On the 2026-11-04 launch the Pages CDN kept serving old CSS at plain URLs next to new HTML, which broke the live site for everyone, not just one browser cache.
- Do not add `picture{display:contents}` to `base.css`: `.svc_img`, `.wall` and others rely on
  `<picture>` being a box.
- Homepage = two explicit flex columns (`.wall`/`.wall_col` in `landing.css`), not CSS columns, so
  the owner's photo order is exact. To reorder, move the `<a>` lines in `index.html`. The photos
  are 3:2 or 4:5, so swapping like for like keeps the columns level.
- The homepage `<link rel="preload">` must carry `fetchpriority="high"` **on the link itself**, and
  must point at the first photo in the wall. The preload scanner starts that request before the
  `<img>` is parsed, so a hint on the `<img>` alone never applies.
- `/galleries` rows are very wide and short (about 4:1), so crops are tight. Each photo's focal
  point is an `.r_item img[src*="…"]` rule in `gallery_list.css`. Check by eye after changing a
  cover. The "Work" h1 on that page is `sr_only` on purpose (owner removed the visible heading).
- Galleries use **uncropped 2-column CSS-columns masonry** (`.gallery_masonry`, 1 col
  <600px). No cropping — best for a photographer.
- **Masonry images ship a mobile-only `<source media="(max-width: 600px)">` carrying a
  single 1600w WebP — deliberately "unoptimized."** Press-and-hold → Save on a phone hands
  the OS whichever srcset candidate is already cached, so a responsive grid saves a
  thumbnail (the owner hit this: 960w saves, ~88KB). One lone candidate removes the
  browser's choice, so long-press anywhere in the grid saves 1600px. Emitted by
  `buildPicture()`/`mobileSrc()` in `tools/rewrite-html.mjs`
  (`GALLERY_MOBILE_MEDIA` + `GALLERY_MOBILE_WIDTH`); masters smaller than 1600w fall back to
  their largest rung. The breakpoint must stay in sync with the 1-column rule in
  `gallery_page.css`. Do not "fix" this as an oversized-image Lighthouse warning — it will
  cost points on gallery pages (see backlog #4) and that is the accepted trade.
  **Sizing history (2026-09-14):** tried 2400w first, which took the 59-photo Wagner gallery
  from 6.8MB → 26.4MB on mobile; owner felt it and we settled on 1600w (13.1MB). 1600px
  still beats Instagram's 1080px upload cap and prints at 5×7, so the extra 13MB bought
  pixels almost nobody sees. Don't re-raise it without re-measuring page weight.
- The lightbox (`gallery-lightbox.js`) opens `data-full` (largest WebP), **not** `img.src`
  (the 1600w JPG fallback) — same reason: one unambiguous resource to save.
- **Files are mixed CRLF/LF.** Node scripts that rewrite HTML must detect per-file EOL
  (`c.includes("\r\n") ? "\r\n" : "\n"`). Git autocrlf warnings on commit are harmless.
- **Headless-Chrome screenshots** below ~480px clip the right edge — a capture artifact,
  NOT real overflow. Verify layout at ≥480px. Serve from a fresh port to dodge disk cache;
  use `--disable-features=LazyImageLoading,LazyFrameLoading --run-all-compositor-stages-before-draw`
  and a long `--virtual-time-budget` so lazy images paint before capture.
- Contact form backend = **Formspree `/f/mbdpgqay`** (method=post). Instagram
  `@pottsey.photos`. Direct email `rowanpotts2005@gmail.com`.
- Keep pages that look redundant but aren't: `football.html` (live `/football` hub),
  `selected-work.html` (deliberate meta-refresh redirect → `/featured-works`).
- The `.book` line at the end of gallery pages shows a price on `graduation.html` only. The owner
  removed prices from every other gallery page; new galleries use the generic line.
- **`football.html`'s game-gallery rows are ordered newest-first.** When adding a new
  football game gallery, put its `r_item` row first (it becomes the LCP image — give it
  `loading="eager" fetchpriority="high"` and demote the previous first row to
  `loading="lazy"`).
